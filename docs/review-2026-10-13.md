# Independent review record, October 13, 2026

Researcher-only. This is the written record of the "Independent review" workstream
(docs/plan.md, "Development subagent execution plan"): what was reviewed, every finding,
how each was verified, and what was done about it. It contains no credentials and must
never reach an agent image, container, prompt, tool result or the conference library
(docs/interfaces.md, "Researcher-only paths").

Nothing in this review ran Docker, Lean, a provider or a paid call (plan row "Execution
hold"). Every confirmation below is offline: code reading, offline reproductions with fakes
or mocks, and the offline test suites. Items that need the validation VM are listed in
"Remaining work".

## Scope and method

* **Seven review dimensions**, matching the workstream's brief (fidelity, isolation, race
  arbitration, logging, evaluator independence, configuration):

  | Dimension | Prefix | Findings |
  | --- | --- | --- |
  | Spending and credentials | `SPEND-` | 7 |
  | Agent isolation | `ISO-` | 5 |
  | Conference services and race arbitration | `CONF-` | 6 |
  | Operational judge | `J` | 6 |
  | Independent evaluator | `EVAL-` | 7 |
  | Agent runtime and logging | `RT-` | 6 |
  | Paper and plan fidelity, documentation | `F` | 8 |

* **Adversarial verification.** Each finding was re-examined by a separate verifier whose
  task was to refute it: re-read the cited code, reproduce the failure offline where
  possible, and re-rate the severity. A finding is **confirmed** only if the verifier could
  not refute it; refuted findings are listed with the reason.
* **Fixes.** Confirmed findings went to six fixers, each confined to its workstream's
  files (docs/interfaces.md, "File ownership"): FX1a (Inspect adapter, runtime,
  compatibility check), FX1b (agent image and runtime probes), FX2 (launch gates, provider
  limit, spending scripts, for the integrator), FX3 (conference, seeded mechanism, tools,
  prompts), FX4 (judge and dataset validation, docs/judges.md), FX5 (evaluator). Cross-file
  interface changes were agreed first as X1–X6 (docs/interfaces.md, "Interface change
  log"). An integration check then reconciled the fixers' interfaces and ran both suites.

## Refuted findings

* **SPEND-1.** A real check cannot produce passing evidence that still has an uncertain
  hold: such holds fail the required checks `no_sample_error` or `provider_cost_reported`,
  so a re-run is needed anyway, and the ledger's cumulative committed total then covers the
  new evidence. The X4 change removed the remaining edge case regardless.
* **CONF-3.** The conference reply carries the operational judge's own `stage`, `reason`
  and compile status for the same source, and the check ties outcome and stage together;
  the judge's handling of statement changes is validated separately by `validate_judge.py`.
* **CONF-6.** The deviation is fully recorded in research/analysis/fidelity_ledger.md
  (summary items 3–4 and row B3, citing plan row "Answer-field density"); the plan row
  names no particular file.
* **F2.** Every paid launch already needs explicit user acts (`paid_launch_enabled`,
  `--launch-paid-pilot`, a typed confirmation of the remaining allowance), the $20 pilot cap
  is enforced by the ledger, and the compatibility check needs a per-run approval flag and
  typed confirmation. A hard block would also stop a retry after an aborted first launch.
